# Security Policy

## Reporting Security Vulnerabilities

If you discover a security vulnerability in this project, please report it by:

1. **DO NOT** create a public GitHub issue
2. Email the project maintainer directly (if available)
3. Provide detailed information about the vulnerability
4. Allow reasonable time for a fix before public disclosure

## Security Best Practices

### For Users

#### 1. API Key Management
- **NEVER** commit API keys to version control
- Store API keys in `.env` file (git-ignored by default)
- Use environment variables for sensitive data
- Regularly rotate your API keys
- Review and revoke unused API keys

#### 2. Configuration Security
```bash
# Copy example config and add your API keys
cp .env.example .env
# Edit .env with your actual keys (NEVER commit this file)
nano .env
```

#### 3. Download Safety
- Only download videos you have rights to download
- Be aware of copyright and fair use laws
- Scan downloaded files with antivirus software
- Use the tool responsibly and ethically

#### 4. System Security
- Keep Python and all dependencies up to date
- Review `requirements.txt` for known vulnerabilities
- Use virtual environments to isolate dependencies
- Regularly update yt-dlp for security patches

### For Contributors

#### 1. Code Security
- Never hardcode API keys, passwords, or secrets
- Use environment variables for configuration
- Validate and sanitize all user inputs
- Follow secure coding practices
- Review dependencies for known vulnerabilities

#### 2. Commit Hygiene
- Review all changes before committing
- Use `.gitignore` to prevent accidental commits
- Never commit:
  - API keys or tokens
  - Personal configuration files
  - Downloaded content
  - Log files with sensitive data
  - Database files

#### 3. Dependency Management
- Pin dependency versions in `requirements.txt`
- Regularly check for security updates
- Review new dependencies before adding
- Use tools like `pip-audit` or `safety` to scan for vulnerabilities

```bash
# Check for known vulnerabilities
pip install pip-audit
pip-audit
```

## Security Checklist Before Publishing

- [ ] All API keys removed from code and config files
- [ ] `.gitignore` properly configured
- [ ] `.env.example` created with placeholders
- [ ] `config.yaml.example` has no real credentials
- [ ] README updated with security instructions
- [ ] Dependencies reviewed for vulnerabilities
- [ ] Sensitive logs and debug files excluded
- [ ] Download history files excluded (may contain personal data)

## Protected Files and Directories

The following are automatically excluded from version control (see `.gitignore`):

### Critical - Never Commit
- `.env` - Contains actual API keys
- `config.yaml` - May contain actual API keys (use `config.yaml.example` instead)
- `*.key`, `*.pem`, `*.p12` - Any key files
- `logs/` - May contain sensitive debug information
- `downloads/` - Personal downloaded content

### Generated/Temporary
- `venv/`, `.venv/` - Virtual environment
- `__pycache__/` - Python cache
- `*.pyc` - Compiled Python files
- `activate_env.sh`, `run_downloader.sh` - Generated by setup

## Common Security Mistakes to Avoid

### ❌ DON'T DO THIS:
```yaml
# config.yaml - WRONG!
gemini_api_key: "AIzaSyBiCqMPhW9fkZUTnmSFEvQjnOUx1N62RA8"
```

### ✅ DO THIS INSTEAD:
```yaml
# config.yaml - CORRECT!
gemini_api_key: ""  # Use GEMINI_API_KEY environment variable
```

```bash
# .env file (git-ignored) - CORRECT!
GEMINI_API_KEY=AIzaSyBiCqMPhW9fkZUTnmSFEvQjnOUx1N62RA8
```

## API Key Exposure Response

If you accidentally committed an API key:

1. **Immediately revoke the exposed key** from your provider's dashboard
   - Gemini: https://makersuite.google.com/app/apikey
   - OpenAI: https://platform.openai.com/api-keys

2. **Generate a new API key**

3. **Remove from git history** (if already pushed):
```bash
# Use git filter-branch or BFG Repo-Cleaner
# Or create a fresh repository if necessary
```

4. **Update your `.env` file** with the new key

5. **Add the exposed key to `.gitignore`** if not already present

## Privacy Considerations

### Download History
- The application tracks downloaded videos in `download_history_*.json`
- This file may contain personal viewing habits
- It's excluded from git by default
- Delete periodically if privacy is a concern

### Logs
- Log files may contain search queries and video titles
- Review logs before sharing for debugging
- Logs are excluded from git by default
- Use `log_level: "WARNING"` or `"ERROR"` to reduce verbosity

### AI Debug Logs
- AI debug logs in `logs/ai_debug/` contain full prompts and responses
- May reveal search patterns and preferences
- Excluded from git by default
- Delete if sharing workspace

## Compliance
